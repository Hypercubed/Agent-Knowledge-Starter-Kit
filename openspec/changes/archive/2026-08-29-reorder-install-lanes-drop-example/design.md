## Context

Current install docs present four lanes (bootstrap-first via direct `node bootstrap.mjs`, manual `npm i -g`, `cp example/.agents`, agent-assisted `npx skills add` prompt) as peers. `example/` is a committed snapshot generated by `generate-example/run.sh` (`npx skills add --copy` + `cp bootstrap/*`), missing `openwiki/`/`openspec/`, and requires re-generation each release (drift seen in fixes for `internal:true` ordering, `skills --full-depth`, verbose logging). Both preferred lanes already converge on `aksk-bootstrap/SKILL.md` + `scripts/*.mjs` (peer checks via `check_peer_tools.mjs`, contract via `attach_wiki_contract.mjs`, routing via `attach_section.mjs`, baseline via `init_agents_md.mjs`). Skill discovery via `npx skills add` copies whole skill directories including `scripts/*.mjs` and `references/` for each discovered skill, but this repo layout requires `--full-depth` to find all 4 user skills; `.claude-plugin/plugin.json` is loaded by default (lists the 4 user skills, excludes `generate-example` `internal:true`). Remote `npx skills add Hypercubed/Agent-Knowledge-Starter-Kit` fetches `main` (old `scaffold/...` paths) unless a ref is given — post-merge or `@develop` must be documented. See proposal for motivation.

## Goals / Non-Goals

**Goals:**
- Reorder Quick start to 2 lanes: ① Agent-assisted via `aksk-bootstrap` (EXECUTE/INSTRUCT) preferred, ② `npx skills add --full-depth` human fallback; both delegate to the same `aksk-bootstrap/scripts`.
- Delete `example/` (38 files) and the generator so the repo has one source of truth (templates + scripts, not a snapshot).
- Clean shell scripts and playbooks so no `example/`-specific bypass remains.

**Non-Goals:**
- Changing `aksk-bootstrap` runtime (preflight, global lane, per-repo lane, never half-install) — only docs and lane ordering.
- Changing `.claude-plugin/plugin.json` (already correct) or `openwiki`/`openspec` behavior.
- Adding a new runtime skill.

## Decisions

**Decision: Delete `example/` entirely, not freeze it.**
- *Why:* Snapshot duplicates `npx skills add --full-depth` output, omits `openwiki`/`openspec`, and is excluded from wiki via `.openwikiignore /example/`. Keeping a frozen demo would still confuse `Quick start` and require consumers to choose between 3 methods.
- *Alternative:* Keep `example/` as frozen demo, remove generator only — rejected: still a third lane to maintain mentally.

**Decision: Keep `npx skills add` as documented fallback with `--full-depth`.**
- *Why:* Local discovery without `--full-depth` only found 1 skill (`aksk-bootstrap`) due to shallow priority walk (`discoverSkills` → `findSkillDirs` only when `--full-depth` or `skills.length==0`). With `--full-depth` all 4 are found and their `scripts/*.mjs` + `references/` are copied. Documenting this keeps human manual path viable without an agent.
- *Alternative:* Hide `npx` lane entirely — rejected: air-gapped/manual users need it.

**Decision: Agent-assisted prompt clones kit to temp then runs `bootstrap.mjs`.**
- *Why:* `bootstrap.mjs` assumes a kit checkout at `node .agents/skills/aksk-bootstrap/scripts/bootstrap.mjs [repo-root]`. Remote `npx skills add` alone does not create `openspec/`/`openwiki/`. Clone-to-temp covers greenfield repos; INSTRUCT lane covers sandboxed agents.
- *Alternative:* Publish `bootstrap.mjs` as `npx` bin — deferred, clone is sufficient.

**Decision: Clean scripts minimally.**
- `scripts/check-publish.sh`: remove `case example/*) continue` link-check bypass; all tracked `*.md` are real. Keep generic `find .agents` published list.
- `.agents/playbooks/pre-publish.md` and `major-version-release.md`: remove `example/.agents` validation steps; `scripts/check-agents-structure.sh .agents` remains the single gate.
- `.openwikiignore`: remove `/example/` when `example/` is gone.
- `.agents/skills/generate-example/` and `.agents/playbooks/generate-example.md`: delete wholly.

## Risks / Trade-offs

- **[Risk] Consumers relying on `cp example/.agents`** → Mitigation: **BREAKING** noted; `tasks.md` includes migration note in `README`/`INSTALL` (switch to agent-assisted or `npx add --full-depth`); `example/` had no `openwiki`/`openspec` so they already needed extra steps.
- **[Risk] Remote `main` still has old plugin.json (`scaffold/...`) until merge** → Mitigation: docs note `@develop` until `main` catches up; design does not change fetch code.
- **[Risk] Loss of visual fixture for reviewers** → Mitigation: docs show expected tree via `check-agents-structure.sh` output and `bootstrap.mjs` dry-run, not a committed snapshot.
- **[Trade-off] Fewer install options = less confusion, but offline demo gone** — accepted; `git clone --depth 1` + `cp .agents/skills/*` fallback already covers offline.
